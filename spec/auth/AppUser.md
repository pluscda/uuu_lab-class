# Build Spec for AppUser
- database schema: `.\database\auth.sql`

---

## Summary

`AppUser` stores the accounts that can sign in to the CMS. Like `AppRole`, the business primary key is a string (`UserId`) with a separate `pkid` IDENTITY column. Users are assigned roles through the `AppUserRole` junction table (N-N with `AppRole`). `PasswordHash` is strictly backend-only: it is never exposed through the API, is seeded from the SysConfig default password on create, and is only changed via a dedicated reset-password endpoint.

| Item | Detail |
|------|--------|
| Primary Key | `UserId` nvarchar(200) — string PK, immutable after create. `pkid` int IDENTITY is a surrogate identity column (same pattern as `AppRole`) |
| Foreign Keys | None |
| Required Fields | `UserId`, `UserName`, `IsActive` (default 1), `PasswordHash` (backend-generated, never a request field) |
| N-N Relationships | `AppUserRole` (AppUser ↔ AppRole) |
| Primary-Foreign Links | N/A — `AppUserRole` is managed as the N-N relationship |
| Query Filters | keyword (UserId, UserName), IsActive tri-state, PasswordUpdatedTime date range |
| Default Sort | `pkid ASC` (matches existing `AppRole` list) |

## Required Fields

Required (NOT NULL):

- `UserId` — required on create; **immutable on edit** (PK, same rule as `AppRole.RoleId`)
- `UserName`
- `IsActive` — form defaults to `true` (DB default `DF_AppUser_IsActive = 1`)
- `PasswordHash` — NOT NULL in DB but **never supplied by the client**; generated by the backend on create (see PasswordHash Rules)

Optional (nullable):

- `PasswordUpdatedTime` — read-only, set by the backend only (NULL on create; set on password reset)

---

## PasswordHash Rules (backend-only)

`PasswordHash` is never sent to or received from the frontend:

- **Excluded from** `AppUserRequest`, the `AppUser` C# response model, and all Angular models.
- **On CREATE**: read the default password from `SysConfig` where `configKey = 'appConfig'`. `configValue` is a JSON object — extract the `defaultPassword` property. Hash it with SHA-256 and store the result as `PasswordHash`. `PasswordUpdatedTime` stays NULL on create.
  - Hash encoding: `Convert.ToHexString(SHA256.HashData(Encoding.UTF8.GetBytes(defaultPassword)))` → uppercase hex string.
  - If the SysConfig row is missing or the JSON lacks `defaultPassword`, throw `InvalidOperationException` (surfaces as 500 with a clear message).
  - Read `SysConfig` inside the same connection/transaction as the INSERT — no separate repository dependency.
- **On UPDATE**: `PasswordHash` and `PasswordUpdatedTime` are never touched by `PUT /api/app-users`.
- **Reset password**: `POST /api/app-users/{id}/reset-password` re-reads the SysConfig default password, hashes it, and sets `PasswordHash` + `PasswordUpdatedTime = GETUTCDATE()`. Returns 204, or 404 if the user does not exist.

## N-N Relationships

### AppUserRole — AppUser ↔ AppRole

Junction table: `AppUserRole` (`UserId`, `RoleId`) — composite PK, string FKs on both sides.

- **List view**: `RoleCount` column via subquery: `(SELECT COUNT(*) FROM AppUserRole ur WHERE ur.UserId = u.UserId)`.
- **Detail view**: display assigned role labels (`RoleId` list resolved to `RoleName` via the app-roles lookup).
- **Form (edit + new)**: `p-multiselect` of roles (`appendTo="body"`, `maxSelectedLabels="9999"`), option label = `RoleName`, option value = `RoleId`, ordered by `pkid ASC`.
- Request field: `RoleIds : List<string>` (mirrors `AppRoleRequest.UserIds`).
- `RoleIds` populated on GET-by-id only.
- Sync pattern on save (transactional):
  1. `DELETE FROM AppUserRole WHERE UserId = @UserId`
  2. Bulk INSERT rows from `request.RoleIds` (`Distinct()`)
- On DELETE of the user: delete `AppUserRole` rows first, then the `AppUser` row (same transaction).

## Query Filters

- **keyword**: string
  - LIKE on `UserId`, `UserName`

- **IsActive**: bool?
  - Tri-state: null = no filter, true = 啟用 only, false = 停用 only
  - Exact match on `IsActive`

- **PasswordUpdatedTime**: date range
  - `PasswordUpdatedTimeFrom` (inclusive) / `PasswordUpdatedTimeTo` (inclusive, compare `< To + 1 day` since the column is `datetime`)

## API Endpoints

| Method | Route | Notes |
|--------|-------|-------|
| `GET` | `/api/app-users` | List all (includes `RoleCount`) |
| `POST` | `/api/app-users/query` | Filtered query (body: `AppUserQuery`) |
| `GET` | `/api/app-users/{id}` | Get by `UserId` (URL-encoded; includes `RoleIds`) — 404 if missing |
| `POST` | `/api/app-users` | Create — **409 Conflict** if `UserId` already exists; seeds `PasswordHash` from SysConfig default |
| `PUT` | `/api/app-users` | Update by request body (`UserId` from body, immutable); never touches `PasswordHash` — 404 if missing |
| `DELETE` | `/api/app-users/{id}` | Delete (removes `AppUserRole` rows first) — 404 if missing |
| `POST` | `/api/app-users/{id}/reset-password` | Reset `PasswordHash` to the SysConfig default; sets `PasswordUpdatedTime` — 204 / 404 |

No auth attribute exceptions.

## Backend Notes

### Models

`PasswordHash` is deliberately absent from **all** models below.

```csharp
public class AppUser
{
    public int Pkid { get; set; }
    public string UserId { get; set; } = string.Empty;
    public string UserName { get; set; } = string.Empty;
    public bool IsActive { get; set; }
    public DateTime? PasswordUpdatedTime { get; set; }
    // Subquery count of AppUserRole rows for this user
    public int RoleCount { get; set; }
    // Populated on GET by id:
    public List<string> RoleIds { get; set; } = [];
}

public class AppUserRequest
{
    public string UserId { get; set; } = string.Empty;
    public string UserName { get; set; } = string.Empty;
    public bool IsActive { get; set; } = true;
    public List<string> RoleIds { get; set; } = [];
}

public class AppUserQuery
{
    public string? Keyword { get; set; }
    public bool? IsActive { get; set; }
    public DateOnly? PasswordUpdatedTimeFrom { get; set; }
    public DateOnly? PasswordUpdatedTimeTo { get; set; }
}
```

### SQL — SELECT

```sql
SELECT u.pkid, u.UserId, u.UserName, u.IsActive, u.PasswordUpdatedTime,
       (SELECT COUNT(*) FROM AppUserRole ur WHERE ur.UserId = u.UserId) AS RoleCount
FROM AppUser u
```

- `PasswordHash` is **never selected**.
- GET-by-id additionally runs on the same connection:
  `SELECT RoleId FROM AppUserRole WHERE UserId = @UserId ORDER BY RoleId ASC`

### SQL — INSERT (transactional, with SysConfig read)

```sql
-- 1. read default password (same connection/transaction)
SELECT configValue FROM SysConfig WHERE configKey = 'appConfig';
-- parse JSON → defaultPassword → SHA-256 uppercase hex in C#

-- 2. insert
INSERT INTO AppUser (UserId, UserName, IsActive, PasswordHash)
VALUES (@UserId, @UserName, @IsActive, @PasswordHash);
SELECT CAST(SCOPE_IDENTITY() AS int);

-- 3. AppUserRole bulk insert from RoleIds
```

`PasswordUpdatedTime` is omitted (stays NULL on create).

### SQL — UPDATE

```sql
UPDATE AppUser
SET UserName = @UserName, IsActive = @IsActive
WHERE UserId = @UserId
```

- `UserId` immutable; `PasswordHash` / `PasswordUpdatedTime` never in the SET list.
- Then delete-and-reinsert `AppUserRole` in the same transaction.

### SQL — Reset Password

```sql
UPDATE AppUser
SET PasswordHash = @PasswordHash, PasswordUpdatedTime = GETUTCDATE()
WHERE UserId = @UserId
```

### Special Column Notes

- `PasswordUpdatedTime` is stored as UTC (`GETUTCDATE()`); the frontend appends `'Z'` before display (Dapper returns `Kind = Unspecified`).
- No `nchar` columns — no `RTRIM` needed.
- No `DateOnly` columns in this table (query From/To params are `DateOnly` only).

### Service — `core/services/app-user.service.ts`

- Standard six methods + `resetPassword(userId)`.
- String PK: `encodeURIComponent(userId)` in `getById`, `delete`, `resetPassword`.

### Routes (lazy, `/new` before `/:id`)

| Route | Component |
|-------|-----------|
| `/app-users` | app-user-list |
| `/app-users/new` | app-user-form |
| `/app-users/:id` | app-user-detail |
| `/app-users/:id/edit` | app-user-form |

### List Component

- Columns: pkid, 使用者代碼, 使用者名稱, 是否啟用 (p-tag 啟用/停用), 密碼更新時間 (`+ 'Z'`, `yyyy/MM/dd HH:mm`; blank when null), 角色數, actions (檢視/編輯/刪除)
- Filter drawer: keyword, IsActive (tri-state select: 全部/啟用/停用), PasswordUpdatedTime date range (two `p-datepicker`)
- Session storage keys: `app-user-list-filters`, `app-user-list-sort`, `app-user-list-page` (match the exact key pattern used by the existing AppRole list)
- Default sort `pkid ASC`; paginator text `{first}–{last} 筆，共 {totalRecords} 筆`

### Detail Component

- All display fields + assigned roles rendered as tags (`RoleName` resolved via app-roles lookup, loaded with `forkJoin`)
- Toolbar: 編輯 / 刪除 / **重設密碼** (ConfirmationService: `確定要將「${userId}」的密碼重設為系統預設密碼？`) / 返回

### Form Component

- Reactive Forms; `forkJoin` for parallel loading (app-roles lookup + entity in edit mode)
- `UserId`: editable in new mode, **read-only (disabled) in edit mode**
- `IsActive`: toggle/checkbox, defaults to `true` in new mode
- Roles: `p-multiselect` (`appendTo="body"`, `maxSelectedLabels="9999"`)
- No password field of any kind
- MessageService for save results; 409 on create shows duplicate-UserId error

### Delete Confirmation

```
確定要刪除主代碼 <b>${user.pkid}</b>「${user.userId}」？
```

### Sidebar

Group `系統管理 Admin` (exists) — add `使用者 AppUser` (icon suggestion: `pi pi-user`), placed before AppRole entry or after it to match existing ordering convention in `app.ts` `navGroups`.
